ADR-004: Использование Docker и Docker Compose¶

Статус¶

Принято

Контекст¶

Система состоит из нескольких компонентов: - API (FastAPI) - Worker (Celery) - AI API (FastAPI) - PostgreSQL - Redis

Необходимо обеспечить: - Изолированное развертывание компонентов - Единую среду для разработки и продакшена - Простое масштабирование

Решение¶

Использовать Docker и Docker Compose.

Обоснование:

  1. Изоляция — каждый компонент в отдельном контейнере

  2. Воспроизводимость — одинаковая среда везде

  3. Простота — одна команда для запуска всех сервисов

  4. Масштабирование — легко увеличить количество воркеров

  5. Обновление — пересборка одного компонента без остановки всей системы

Структура:

services:
  api:      # FastAPI (порт 8000)
  ai-api:   # AI API (порт 8001)
  worker:   # Celery
  db:       # PostgreSQL (порт 5432)
  redis:    # Redis (порт 6379)

Последствия¶

Положительные¶

  • Единая среда для всех разработчиков

  • Легкое развертывание

  • Изоляция компонентов

  • Возможность горизонтального масштабирования

Отрицательные¶

  • Дополнительный слой сложности

  • Требует знаний Docker

Компромиссы¶

  • Используем Docker вместо виртуальных машин (легче, быстрее)

Альтернативы¶

Альтернатива 1: Виртуальные машины¶

Каждый компонент на отдельной VM.

Причина отклонения: Тяжеловесно, сложно управлять.

Альтернатива 2: Kubernetes¶

Полноценная оркестрация контейнеров.

Причина отклонения: Избыточен для текущего проекта.
