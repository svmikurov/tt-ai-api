Опишите путь кода от вашего ПК до Production
============================================

Путь кода от моего ПК до Production выглядит так:

Локальная разработка
--------------------

Я пишу код на ПК, использую виртуальное окружение или DevContainer,
запускаю тесты локально. После завершения фичи я пущу код в Git-репозиторий.

CI (Continuous Integration)
---------------------------

При создании Pull Request или пуше в develop запускается пайплайн, который:

- Проверяет стиль кода (linter)
- Сканирует зависимости на уязвимости
- Запускает все тесты (unit, интеграционные)
- Собирает Docker-образ сервиса
- Пушит его в локальный Docker Registry

CD (Continuous Delivery)
------------------------

После успешного прохождения CI и код-ревью, при пуше в main/master автоматически
(или после ручного апрува) запускается деплой на Staging-окружение, где прогоняются smoke-тесты.
Затем, после дополнительного подтверждения, деплой идет на Production.

Развертывание
-------------

На серверах используется Docker Compose (или Kubernetes), который подтягивает
новые образы из локального реестра, перезапускает контейнеры без остановки всего сервиса,
а Nginx направляет трафик на новые инстансы.

Мониторинг
----------

После деплоя я проверяю логи и метрики, чтобы убедиться, что система работает стабильно.
