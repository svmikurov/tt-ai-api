===========================
Состав документации проекта
===========================

В документацию проекта должно входить следующее.

.. note::

   Этот список сгенерирован ИИ и используется как ориентир для обучения.


1. Обзор
--------

* **Общее описание сервиса** — что это за сервис, какую задачу решает, для кого.
* **Место в системе** — как сервис связан с другими (кто его вызывает, кого вызывает он).
* **Глоссарий** — список терминов проекта (Task, Exercise, Requestor), чтобы все понимали одинаково.

2. Архитектура
--------------

* **ADR (Architecture Decision Records)** — документы, где написано: «Мы выбрали PostgreSQL, потому что…». Объясняют **почему**, а не только **что**.
* **C4-диаграммы**:

  * **Контекст** — система и её окружение (клиенты, внешние сервисы).
  * **Контейнеры** — из чего состоит система (API, БД, брокер, воркеры).
  * **Компоненты** — что внутри контейнеров (модули, сервисы).
  * **Код** — классы, интерфейсы и их связи. Обычно не документируется
    в виде диаграмм, так как быстро устаревает; вместо этого используется
    самодокументируемый код, аннотации типов и автогенерация диаграмм.

* **Схема потоков данных** — как данные идут: клиент → API → БД → брокер → ответ.

1. API
------

* **OpenAPI-спецификация (Swagger)** — описание всех эндпоинтов: методы, параметры, ответы.
* **Аутентификация и авторизация** — как клиент получает доступ (токены, роли).
* **Формат ошибок** — как выглядят ошибки (например, ``{"error": "..."}``), чтобы клиент понимал.
* **Версионирование** — как поддерживаются старые версии API (``/v1/``, ``/v2/``).

4. Данные
---------

* **ER-диаграмма (PostgreSQL)** — схема таблиц и связей между ними.
* **Структуры MongoDB** — какие коллекции и документы используются (если есть).
* **Резервное копирование и восстановление** — как и когда делаются бэкапы, как восстановить.

5. Разработка и эксплуатация
----------------------------

* **Инструкция по запуску** — как поднять проект (Docker Compose, ``.env``).
* **Как запускать тесты** — команды для юнит-, интеграционных и сквозных тестов.
* **CI/CD** — как автоматически собирается и деплоится проект.
* **Логи и метрики** — где смотреть логи, какие метрики собираются.
* **Мониторинг и алертинг** — что считается нормой, когда приходят алерты.
* **Условия для масштабирования** — при какой нагрузке нужно добавлять ресурсы.
* **Известные ограничения** — что пока не реализовано и почему.
