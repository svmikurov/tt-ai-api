======================================
ADR-005: Предотвращение блокировки API
======================================

Статус
======

**На рассмотрении**


Контекст
========

От клиентов в реальном времени поступают сотни запросов к ML-модели.
Клиенты ожидают получения результата без постоянного опроса сервера.
Синхронный характер ML-модели приводит к блокировке обработки запросов в API.
При переполнении пула обработки новые запросы клиентов не принимаются.
Система деградирует: запросы клиентов перестают обрабатываться.


Решение
=======

Перевести взаимодействие с ML-моделью на асинхронную модель:
вынести блокирующие вызовы из API в фоновый процесс.


Последствия
===========

Положительные
-------------

1. Клиент сразу получает ответ, что запрос принят.
2. Все запросы обрабатываются без деградации по причине загруженности ML-модели.

Отрицательные
-------------

1. Усложнение системы новыми компонентами:
   очередь сообщений, воркер, хранилище запросов, статусов, результатов. 
2. Увеличение числа внешних зависимостей,
   отказ которых влияет на работоспособность системы.
3. Требуется настройка согласованности между новыми компонентами.


Компромиссы
-----------

1. Усложнение системы ради повышения устойчивости.
2. Рост времени разработки и поддержки.
3. Инвестиции в обучение персонала вместо вложений в оборудование, имеющее физический предел.
4. Вместо синхронного ответа клиент получает идентификатор задачи (task_id)
   и отслеживает её выполнение асинхронно (постоянное соединение или опрос).


Альтернативы
============

1. **Вертикальное масштабирование ML-модели**

   Увеличить скорость вычисления ML-модели за счёт модернизации оборудования (CPU, GPU, память).

   Просто в разработке, не требует увеличения компонентов системы.

   Дорого, предполагает нелинейный рост затрат.
   Имеет физический предел оборудования.
   Не решит проблему при дальнейшем росте нагрузки. 

2. **Ограничение количества ожидаемых запросов к API**

   Ограничить количество принятых и поставленных в очередь обработки запросов.

   Просто в реализации, контролируемая деградация системы.
   
   Пользователи, чьи запросы были отклонены, не получают ответа.
   Не решает проблему блокировки API — лишь сокращает число пострадавших клиентов.
