============================================
ADR-004: Выбор стратегии версионирования API
============================================

Статус
======

**Черновик**

Контекст
========

Сервис предоставляет версионирование API для обратной совместимости.

Решение
=======

Выбрана сратегия версионирования через префикс в URL-пути:
``/api/v1/...``, ``/api/v2/...``

**Обоснование**:

- Явность
- Простота

**Альтернативы**:

- **Версия в заголовке (Accept-Version)**: 
  Сложность в отладке, клиент может забыть указать.
- **Версия в query-параметре**: 
  Не RESTful, мешает кешированию.
- **Одна версия с совместимыми изменениями**: 
  Невозможно при Breaking Changes.

Последствия
===========

**Положительные**

- Простота реализации
- Ясность для клиентов

**Отрицательные**

- Увеличение количества ендпойнтов
