========================================================
ADR-007: Вынесение аутентификации на API Gateway
========================================================

Статус
======

**Принято**

Контекст
========

Системе нужна аутентификация пользователей для доступа к API.

**Требования:**

- Безопасная проверка JWT-токенов
- Централизованное управление политиками
- Разгрузка бэкенда

Решение
=======

Вынести аутентификацию на **API Gateway**.

**Обоснование:**

1. **Разгрузка API** — бэкенд занимается только бизнес-логикой
2. **Централизация** — единая точка входа для всех политик
3. **Безопасность** — единый механизм проверки токенов
4. **Масштабирование** — Gateway может быть отдельным компонентом

**Архитектура:**

::

   Клиент → API Gateway (проверка JWT) → FastAPI (бизнес-логика)

**Заголовки:**

- `X-User-ID` — идентификатор пользователя
- `X-User-Role` — роль пользователя

Последствия
===========

Положительные
-------------

- API не знает об аутентификации
- Упрощение кода бэкенда
- Централизованное управление безопасностью

Отрицательные
-------------

- Дополнительный компонент в инфраструктуре
- Требуется настройка Gateway

Компромиссы
-----------

- Выносим аутентификацию вместо встраивания в API (гибче, но сложнее)

Альтернативы
============

Альтернатива 1: Аутентификация в API
------------------------------------

Проверка JWT внутри FastAPI.

**Причина отклонения:** Нарушает разделение ответственности, усложняет код API.

Альтернатива 2: Без аутентификации
----------------------------------

Открытый доступ к API.

**Причина отклонения:** Небезопасно.
