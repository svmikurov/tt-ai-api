========================================================
ADR-002: Использование Celery
========================================================

Статус
======

**Принято**

Контекст
========

ML-модель работает синхронно и может отвечать долго (2-5 секунд).
API не должно блокироваться на время выполнения модели.

**Требования:**

- Асинхронная обработка задач
- Отказоустойчивость (retry при ошибках)
- Масштабируемость (несколько воркеров)
- Мониторинг выполнения задач

Решение
=======

Использовать **Celery** с брокером **Redis**.

**Обоснование:**

1. **Асинхронность** — задачи выполняются в фоне, API не блокируется
2. **Retry** — встроенный механизм повторных попыток
3. **Масштабирование** — можно запускать несколько воркеров
4. **Мониторинг** — Flower для отслеживания задач
5. **Интеграция** — легко интегрируется с FastAPI

Последствия
===========

Положительные
-------------

- API не блокируется на время выполнения модели
- Возможность горизонтального масштабирования
- Встроенный механизм retry
- Мониторинг через Flower

Отрицательные
-------------

- Дополнительная сложность
- Требует настройки брокера (Redis)

Компромиссы
-----------

- Используем Celery вместо прямого Redis (для retry и мониторинга)

Альтернативы
============

Альтернатива 1: Redis напрямую (без Celery)
-------------------------------------------

Worker читает задачи напрямую из Redis.

**Причина отклонения:** Нет встроенного retry, мониторинга, сложнее масштабировать.

Альтернатива 2: RabbitMQ
------------------------

Альтернативный брокер сообщений.

**Причина отклонения:** Redis уже используется для кеша, меньше зависимостей.
