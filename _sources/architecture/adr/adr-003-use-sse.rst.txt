========================================================
ADR-003: Использование SSE для Real-Time уведомлений
========================================================

Статус
======

**Принято**

Контекст
========

Клиенты должны получать результаты ML-модели в реальном времени
без постоянного опроса (polling) сервера.

**Требования:**

- Клиент получает результат сразу после завершения
- Клиент видит промежуточный статус
- Соединение устойчиво к разрывам
- Низкая нагрузка на сервер

Решение
=======

Использовать **SSE (Server-Sent Events)** через библиотеку `sse-starlette`.

**Обоснование:**

1. **Real-time** — сервер сам отправляет результат
2. **Простота** — клиент использует EventSource API
3. **Автопереподключение** — встроено в браузер
4. **Низкая нагрузка** — в отличие от Polling
5. **Поддержка** — работает во всех современных браузерах

**Техническая реализация:**

.. code-block:: python

   from sse_starlette.sse import EventSourceResponse

   @router.get('/stream/{task_id}')
   async def stream_result(task_id: str):
       async def event_generator():
           yield {"event": "status", "data": "waiting"}
           while not task.ready():
               await asyncio.sleep(0.5)
           yield {"event": "complete", "data": task.get()}

       return EventSourceResponse(
           event_generator(),
           headers={"X-Accel-Buffering": "no"}
       )

Последствия
===========

Положительные
-------------

- Real-time уведомления без опроса
- Простой клиентский API
- Автоматическое переподключение
- Низкая нагрузка на сервер

Отрицательные
-------------

- Нет двунаправленного обмена
- Максимум 6 соединений на домен
- Не работает в старых браузерах

Компромиссы
-----------

- Используем SSE вместо WebSocket (избыточен для нашего сценария)

Альтернативы
============

Альтернатива 1: Polling
-----------------------

Клиент опрашивает сервер каждые 0.5-1 секунду.

**Причина отклонения:** Высокая нагрузка на сервер, задержка в доставке.

Альтернатива 2: WebSocket
-------------------------

Двунаправленное соединение.

**Причина отклонения:** Избыточен, сложнее в реализации.

Альтернатива 3: Long Polling
----------------------------

Удержание соединения до получения ответа.

**Причина отклонения:** Сложнее, больше нагрузка на сервер.
